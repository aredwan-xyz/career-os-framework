# Contributing to Career OS

Thank you for wanting to improve this resource. Here's how to contribute effectively.

---

## What We're Looking For

### High-value contributions
- **New AI prompts** — if you've found a prompt that works significantly better than the existing ones, add it with context on when and why to use it
- **Template improvements** — clearer structure, better examples, or more actionable formatting
- **Tool additions** — new tools in the automation stack that provide clear value (include cost, use case, and how to set it up)
- **Playbook gaps** — scenarios that aren't covered (e.g. career transitions, returning after a gap, international job search)
- **Real-world validation** — if you've used this system and something worked differently than described, open an issue

### What we're not looking for
- Generic career advice that duplicates what's already here
- Promotional content for tools or services
- Content that requires paid resources without free alternatives
- Vague additions that lack specificity or actionable steps

---

## How to Contribute

### Reporting an issue
Open a GitHub issue with:
- Which file and section the issue is in
- What the problem is (outdated info, unclear instructions, broken link, etc.)
- Suggested fix if you have one

### Submitting a pull request
1. Fork the repository
2. Create a branch: `git checkout -b improve/module-name-change-description`
3. Make your changes
4. Write a clear PR description: what you changed, why, and any tradeoffs
5. Submit the PR

### PR guidelines
- One change per PR (don't bundle unrelated improvements)
- Match the existing tone and format of the file you're editing
- If adding a new prompt, test it first and include example output
- If adding a new tool, include: URL, cost, setup steps, and what it replaces or complements
- Keep language direct and action-oriented — no fluff

---

## Style Guide

- **Tone:** Direct, confident, practical. No motivational filler.
- **Formatting:** Use tables for comparisons, code blocks for templates/prompts, checklists for deliverables
- **Templates:** Always use `[brackets]` for required customization fields
- **Examples:** Concrete over abstract — show a filled-in example whenever possible
- **Length:** Long is fine if every sentence is earning its place. Cut ruthlessly otherwise.

## Questions

Open an issue with the `question` label. We'll respond within a few days.
